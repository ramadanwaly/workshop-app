# نظام إدارة ورشة الأثاث والتكاليف المالية
# Workshop Financial Management & ERP System

نظام لإدارة تشغيل ورش الأثاث والتصنيع، بيحل محل الدفاتر الورقية والحسابات اليدوية. كل الحسابات المالية محصورة داخل قاعدة البيانات نفسها كمصدر وحيد للأرقام، عشان يمنع تضارب الأرقام أو التلاعب بالمدفوعات والمصروفات. الواجهة مصممة للاستخدام المباشر داخل الورشة عبر الموبايل أو التابلت.

---

## 1. المعمارية وتصميم النظام

النظام مبني على معمارية متعددة الطبقات، بحيث دقة الحسابات وأمن البيانات ما يعتمدوش على متصفح العميل:

```text
[ واجهة الاستخدام (موبايل / حاسوب) ]
                │
                ▼ (اتصال مشفر HTTPS / ترويسات أمان / خادم عكسي)
[ طبقة الخادم والتطبيقات (Next.js 14 App Router) ]
                │
                ▼ (Server Actions / تحقق عبر Zod / صلاحيات RBAC)
[ طبقة عميل قاعدة البيانات (Supabase Client Session) ]
                │
                ▼ (أقفال المعاملات / دوال ذرية RPC / قوادح Triggers)
[ محرك قاعدة البيانات (PostgreSQL 17 Engine) ]
  ├── المصدر الوحيد للحقيقة (Views للحسابات التجميعية)
  ├── قادح منع السحب المكشوف (Advisory Lock + Trigger)
  ├── منع التكرار الذري (Atomic Idempotency)
  └── سجل تدقيق مالي غير قابل للتعديل (Immutable Audit Log)
```

طبقة العرض مبنية بـ Next.js 14، وبتقدّم شاشات للإدخال اليومي زي تسجيل يوميات العمال وبنك الخامات الفائضة وشراء المستلزمات، مع عرض حالة الخزينة وتنبيهات السيولة لحظيًا.

طبقة خادم التطبيق تستقبل طلبات الإدخال عبر Server Actions فقط، وتتحقق من البيانات بمخططات Zod، وتفصل صلاحيات المالك (Owner) عن المدير (Staff)، وتنضّف البيانات المرجعة قبل إرسالها للواجهة.

طبقة محرك البيانات هي اللي بتنفّذ كل العمليات المحاسبية، وحساب التكاليف المباشرة، وتسويات أجور العمال، وجداول دفعات المقاولين، عبر Views ودوال RPC داخل PostgreSQL 17 — فمفيش أي حسابات مالية عائمة في كود الواجهة.

## 2. المكدس التقني (Tech Stack)

- **إطار العمل**: Next.js 14 (App Router) لتوجيه محمي على مستوى الخادم.
- **لغة البرمجة**: TypeScript (Strict Mode) يمنع أخطاء المدخلات غير المعرّفة.
- **قاعدة البيانات**: PostgreSQL 17 عبر Supabase، مع التحكم بالوصول على مستوى السطر (RLS).
- **فحص المدخلات**: Zod، لمطابقة كل مدخل قبل ما يوصل لقاعدة البيانات.
- **الحوسبة**: Docker و Docker Compose، بيئة Alpine خفيفة ومتعددة مراحل البناء.
- **الاستضافة**: خادم محلي خاص (Self-Hosted / VPS)، عشان البيانات المالية تفضل تحت سيطرة كاملة بدون خدمات سحابية خارجية.

## 3. القواعد المحاسبية الثابتة

قاعدة البيانات بتفرض 5 قواعد ماينفعش تتكسر تحت أي ظرف:

**رصيد الخزينة اللحظي**: رصيد الخزينة المتاح = إجمالي تمويلات المالك ناقص إجمالي المسحوبات النقدية الفعلية. المعاملات الملغاة، والمعاملات المسددة مباشرة من جيب المالك، بتتستبعد تلقائيًا من خصومات الخزينة.

**سداد المالك المباشر**: لو المالك دفع قيمة خامات أو مستلزمات من حسابه الشخصي، النظام يفرض ربط المعاملة بمشروع محدد. القيمة تتضاف فورًا لتكلفة المشروع المباشرة، وما تتخصمش من خزينة الورشة النقدية نهائيًا.

**بنك الفوائض وإعادة تدوير الخامات**: إرجاع الفائض يقلل التكلفة الفعلية للمشروع المصدر ويضيف الخامة لبنك الفوائض، من غير أي تأثير نقدي على الخزينة. استهلاك الفائض يزيد تكلفة المشروع المستلم بالقيمة المقدرة للخامة، من غير حركة سحب نقدية جديدة.

**أجور العمال وسلفهم**: السلف تتخصم مباشرة من نقدية الخزينة، ومش بتتحسب كتكلفة مباشرة على أي مشروع. يوميات العمل غير المسواة تتحسب ضمن تكلفة المشروع المباشرة وتتسجل كالتزام مستحق على الورشة. التسوية الدورية تصرف صافي الاستحقاق فقط (اليوميات المكتسبة ناقص السلف المسحوبة) من نقدية الخزينة.

**مقاولو الباطن وعقود التوريد**: قيمة العقد الإجمالية تثبت تكلفة المشروع من لحظة التعاقد. الدفعات النقدية المرحلية تقلل الالتزام المالي ورصيد الخزينة، من غير ما تكلفة المشروع تتحسب مرتين.

## 4. أنماط التصميم والتحصين الأمني

### أ. منع تكرار العمليات الذري

كل معاملة مالية بتاخد مفتاح فريد UUID مقيد بالسياق (key, user_id, action). دورة منع التكرار كلها بتدار داخل دالة RPC ذرية واحدة (rpc_record_treasury_transaction)، عن طريق قفل سطري استباقي SELECT ... FOR UPDATE ونمط الإدراج الشرطي INSERT ... ON CONFLICT DO NOTHING. في حالة إعادة الإرسال غير المقصودة، النظام يرجّع استثناء مخصص (IdempotencyError) بدل رسالة نظام عامة.

### ب. منع السحب على المكشوف وقفل التزامن

فحص كفاية رصيد الخزينة اتنقل من طبقة التطبيق لقادح قاعدة بيانات مباشر (BEFORE INSERT ON treasury_transactions)، عشان يمنع ثغرات السباق الزمني (TOCTOU). بيتحجز قفل استشاري لحظة التنفيذ:

```sql
PERFORM pg_advisory_xact_lock(hashtext('treasury_balance_lock'));
```

مدير الورشة (Staff) ممنوع نهائيًا من تسجيل أي مصروف يخلي الخزينة سالبة. المالك (Owner) بس اللي يقدر يتجاوز، ولو تجاوز بيتسجل تنبيه تدقيقي فوري (treasury_overdraft).

### ج. أمان تصدير البيانات

مخرجات الـ Server Actions كلها بتمر على طبقة تطهير بتستبعد المعرّفات الداخلية والبيانات الحساسة (زي created_by، voided_by، updated_by) عشان تمنع تسريب هيكلية النظام الداخلية للمتصفح.

### د. حماية الخادم العكسي والمسارات

عناوين IP للمستخدمين بتتستخرج من قراءة آخر عنوان في هيدر X-Forwarded-For، عشان يمنع تزييف الهوية والتحايل على حدود المعدل (Rate Limiting). توجيه الروابط بعد تسجيل الدخول محصّن بـ Regex بيرفض هجمات التوجيه المفتوح وحيل الشرطة المائلة المعكوسة (/\).

## 5. قاعدة البيانات والترحيلات

النظام فيه 35 ملف ترحيل متسلسل، مطبّق بالكامل ومنضبط تاريخيًا. سكربت النشر (scripts/apply-migrations.sh) بيسجل بصمة sha256 لكل ملف داخل جدول supabase_migrations.schema_migrations، عشان يمنع أي تعديل لاحق على ملفات الترحيل ويضمن استقرار المخطط. الـ Row-Level Security مفعّل على كل الجداول (أكتر من 17 جدول)، ودور anon و PUBLIC مجرّد من أي صلاحية وصول عشوائي، ومفيش سياسة وصول مفتوحة USING (true) في النظام.

## 6. الجودة واختبارات الاعتمادية

فيه أكتر من 358 اختبار آلي (تكاملي ووحدات) بيغطي مسارات المعاملات، ودقة مخططات Zod، وحالات سباق العمليات المتزامنة. فيه كمان سكربت فحص دخان مستقل (scripts/verify-db.sh --db <name>) بيختبر سلامة الدوال وتماسك الـ Views وجاهزية القوادح ضد قواعد بيانات جديدة، عشان يتأكد إن مفيش تبعيات مكسورة.

## 7. التشغيل السريع

**المتطلبات**: بيئة Docker و Docker Compose، وNode.js 20+ لو هتشتغل محليًا.

**الخطوات**:

استنساخ المستودع وضبط المتغيرات:
```bash
git clone <REPO_URL> && cd workshop-app
cp .env.example .env.production
```

تطبيق ترحيلات قاعدة البيانات:
```bash
./scripts/apply-migrations.sh
```

بناء وتشغيل حاوية التطبيق:
```bash
docker compose up -d --build
```

فحص سلامة المخطط المالي:
```bash
./scripts/verify-db.sh --db postgres
```
